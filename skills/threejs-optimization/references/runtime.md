# Three.js 运行时优化

## 定位 CPU 与 GPU 瓶颈

- 从真实交互入口采集浏览器 Performance trace。用帧间隔衡量流畅度，按主线程调用栈归因 JS、布局、GC、解析和上传提交。单独标记动画、物理、拾取与渲染提交。给 `renderer.render()` 包一层计时只能衡量该调用的 CPU 侧耗时。
- WebGL 用 `renderer.info` 查看提交量和资源数。多次 render 或后处理时，设置 `autoReset = false`，在统一的帧边界调用 `reset()`，并在完整帧后读取统计。确认该版本和后端的统计口径。纹理和几何计数以对象为单位，显存字节数需单独估算。
- WebGL2 支持 `EXT_disjoint_timer_query_webgl2` 时可采集 GPU 时间。限定待处理查询数，在后续帧轮询，丢弃 disjoint 样本并回收查询对象。WebGPU 按已安装版本与实际后端检查 timestamp query 支持。缺少 GPU 计时时，使用下列对照实验并标为推断。GPU 与 CPU 可并行执行，分别报告时间。
- 固定 CSS 尺寸、相机与对象数量，临时降低绘制缓冲区尺寸。若 GPU 时间或帧间隔随像素数显著改善，检查片元、过度绘制和全屏 pass。再分别隔离阴影与后处理。若像素变化影响小，且单独降低几何复杂度有收益，检查顶点、骨骼和 morph 开销。draw calls 多且主线程提交耗时高时，优先试小范围合批。帧率被刷新率封顶时，用可用的阶段耗时识别收益。

## 按证据选择改动

| 现象 | 优先试验 | 回归检查 |
| --- | --- | --- |
| 每帧 JS、GC 或 Vue 更新过重 | 复用经 trace 确认的热点临时对象。让高频 Three.js 对象避开深响应式，例如按所有权使用 `markRaw` 或 `shallowRef`，UI 指标低频同步。静态场景可用按需渲染 | 控件阻尼、动画、资源就绪、resize 和状态变化能请求新帧 |
| 矩阵遍历、拾取、动画或物理过重 | 减少每帧全场景遍历，缓存可拾取集合，限定 raycast 层和频率。仅对确认静态且矩阵已更新的对象禁用自动更新。按需降低远处对象更新频率 | 层级变换、离屏动画恢复、拾取精度与物理步长 |
| CPU 渲染提交过重 | 相同几何和材质的重复对象试 `InstancedMesh`，静态同材质对象按空间分块合并。先检查 geometry groups 和多材质导致的 draw calls | 边界盒、视锥裁剪、实例拾取与高亮、可见性和透明排序 |
| GPU 像素或带宽压力 | 限制 DPR，降低阴影或后处理分辨率，压缩 pass 数，减少透明叠绘与昂贵材质。按目标设备设置档位 | UI 清晰度、透明效果、阴影、色彩和切换稳定性 |
| GPU 顶点压力 | 使用有视觉误差预算的 LOD，限制可见对象，按需要减少三角形、蒙皮或 morph 工作量 | 轮廓、切级抖动、动画与附件位置 |
| 首次显示或切场景卡顿 | 分段量下载、解析、解码和首帧。缓存复用解码器，限制并发，按需分批上传。在证实编译造成卡顿时考虑预热 shader | 首帧、加载峰值、取消切场景和重复进入 |

## CPU、Worker 与 GPU 的计算分配

以现有业务行为为约束。先用相同输入记录当前场景的状态、事件顺序、动画和交互结果。找出数据由谁持有、何时更新、谁需要读取，再判断已测得的热点是否值得调整执行位置。

| 执行位置 | 选择依据 |
| --- | --- |
| 主线程 CPU | 保留业务状态和规则的现有执行路径。输入处理、依赖同一帧结果的拾取或碰撞判定，以及数据量较小的计算，优先在现有路径减少遍历、分配和重复计算 |
| CPU Worker | 已测得的纯计算热点可以异步完成，且现有调用者仍能在原有时序拿到结果。比较 TypedArray 转移或复制、队列等待与并发开销，核对过期结果和返回顺序 |
| GPU | 大量数据可并行处理，结果可直接留在 GPU 供渲染使用时，评估顶点变形或纯视觉粒子等候选。若 CPU 同帧需要变形后的位置做拾取、碰撞或挂点，先保证这些结果与现有行为一致，否则保留原执行路径 |

用现有渲染后端做最小范围试验。按项目锁定的 Three.js 版本、实际后端及目标设备探测所需能力和限制。为缺少能力或初始化失败的场景保留经验证的原有计算路径。GPU 渲染后端的回退需要单独验证所用计算功能。

对照时把上传、提交、GPU 执行、回读或同步等待纳入端到端测量，同时比较帧间隔 p95、输入响应和内存峰值。用同一输入回归状态变化、事件顺序、动画和拾取结果，数值误差沿用项目已有容差。仅在目标场景流畅度有可重复改善且业务行为通过回归时采用候选。

## 归因与释放内存

- **JS 堆与浏览器资源。** 对加载前、加载后、卸载后的同一状态取堆快照，并重复场景往返。对比 retained size 和 retaining paths，检查 Vue watcher、事件、定时器、RAF、缓存、AnimationMixer、ArrayBuffer 和闭包。浏览器进程或 Worker 的原生内存以及 GPU 分配不能仅靠 JS 堆快照确认。
- **显存估算。** 按独立资源去重。RGBA8 每级按宽 × 高 × 4 字节估算，完整 2D mip 链在大尺寸下约为基准级的 4/3。块压缩纹理逐级按块数和块字节数计算，并按实际转码格式、面数或层数统计。几何按唯一顶点与索引缓冲区计数，另计阴影贴图、环境贴图、颜色与深度附件、MSAA 和 resolve 目标。注明驱动开销、共享和采样数等假设。
- **峰值。** 检查 GLB 原始缓冲、解码数据、图像和上传资源同时存在的时段。限制下载、解码及转码并发，给场景或缓存设置生命周期。需要在切场景时短暂保留两套资源时，单独测这个窗口。
- **所有权。** 场景或组件退出时停止其 RAF、订阅和监听，停止所属动画并按所有权清除 mixer 缓存。异步结果返回时检查当前场景或请求代次，处置已失效的独占结果。对离场资源按引用或资源管理器释放 geometry、material、texture、render target、pass 和 skeleton。共享对象在最后一个所有者退出后释放。Texture 与材质分别管理，`ImageBitmap.close()` 需等最后一个使用者退出且无需再次上传时调用。全局 renderer 与共享 loader 的寿命由其拥有者管理。
- **复测。** 重复进入和退出并比较稳定后的堆、资源计数和峰值。内部渲染缓存可在首轮后保持稳定。逐轮增长再按引用链归因。
