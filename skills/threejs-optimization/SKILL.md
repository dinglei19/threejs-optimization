# Three.js 性能优化

围绕用户指定的场景、设备和指标完成优化，保留现有画质、业务规则、状态更新顺序和可观察交互结果。仅审计时交付证据和优先级。收到优化请求时，在当前任务内完成基线、定位、实施、复测和汇总。

- 涉及帧率、主线程、CPU/GPU 计算分配、渲染开销、内存增长或资源释放时，读取 [运行时优化](references/runtime.md)。
- 涉及 GLB/glTF 检查、压缩、减面、合批或加载器兼容时，读取 [GLB 优化](references/glb.md)。若目标是显存、加载峰值或帧率，同时核对运行时的相关指标。

## 自主推进

- 从当前对话、项目配置、运行入口和现有工具确认 Three.js 版本、渲染后端、目标设备、场景与资源加载路径。优先自行运行场景、采集基线和复测数据，复用已有测试脚本与可用的登录测试环境。
- 按瓶颈影响和回归风险排序，逐项验证并落地范围内的候选。进度更新用于同步证据和结果。当前一项完成后，直接推进下一个有证据支撑的候选，直到剩余候选收益无法验证、触及用户约束或存在实际阻塞。
- 只有缺少无法自行取得的关键前提或必须由用户决定的取舍时，集中说明所需信息及其影响，同时完成其余可独立推进的工作。某项指标暂时无法实测时，保留已验证的结果，标明缺测项和具体原因。

## 工作流程

1. **固定对比条件。** 优先使用生产构建，固定浏览器、设备、视口、绘制缓冲区尺寸、DPR、场景、相机与交互路径。分开采集冷启动、预热后运行和重复加载卸载。目标帧预算按用户指定帧率计算，例如 60 FPS 对应约 16.7 ms。
2. **保留基线。** 运行时按目标采集帧间隔 p50/p95、主线程耗时、可用的 GPU 耗时、draw calls、三角形、JS 堆或资源计数。加载问题记录实际传输量、从加载到可用或首帧的耗时及峰值。离线优化记录文件字节数、纹理尺寸、primitive、三角形、动画和扩展。
3. **用对照隔离瓶颈。** 每轮只改变一个主要变量，重复相同场景。明确区分浏览器实测、静态统计、估算和推断。缺少可复现入口或目标设备时，继续完成可验证的静态工作，并明确待测指标。
4. **实施可回退的改动。** 优先复用项目的渲染循环、资源所有权和加载器。保留原始模型，先生成候选文件，验证后再按请求接入。把节点命名、动画、骨骼、交互、画质和兼容性当作验收条件。
5. **复测单项与最终组合。** 沿用基线的测试入口、采样方式和操作路径。条件可比时，对最终组合再跑一轮，检查叠加后的收益和回归。遇到后台限帧、GPU 计时失效或条件漂移时，剔除无效样本并在条件可控时重测。

## 最终交付

- 列出已落地的优化点，说明对应瓶颈、实际改动和代码或资产位置。
- 给出前后对比表，包含指标与单位、优化前、优化后、变化量或百分比，以及必要的测量条件或数据来源。标明实测、静态统计、估算或缺测。差异落在测量波动内时，写明未见稳定改善。
- 说明回归检查结果和剩余限制。模型交付附候选路径、转换命令、所需解码器与验证结果。
